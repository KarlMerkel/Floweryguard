# Локальный кандидат Flowery 1.3.0

Дата подготовки: 27 октября 2026 года. Файлы не опубликованы.

## Комплект

Каталог: `dist/Flowery-v1.3.0-portable/`. Запуск: `start.bat` из этой папки, завершение: пункт `0` или `Ctrl+C`. Python пользователю не нужен. Настройки комплекта независимы от прежних папок. Прежние EXE в корне проекта и `Flowery_Release` оставлены без замены.

Сборка: Python 3.11.9 x64, PyInstaller 6.22.3, команда `python build_local.py`. Версия в ресурсах EXE — `1.3.0`.

SHA-256 `Flowery.exe`:

```text
173dceae45dffe56f5da2a1bcdf3982b32b11c03d9356c672cb5062484c8b8bb
```

При новой сборке сумма может измениться; актуальная сумма создаётся в `SHA256SUMS.txt` рядом с EXE.

Комплект обновлён после [проверки неполной загрузки страниц](page-loading-v1.3.0.md): теперь после зависания меняется также техника обхода. 523 автономных теста проходят; обновлённый EXE повторно прошёл справку и просмотр статуса с внешним конфигом. Полное восстановление указанных сайтов не подтверждено. Описанный ниже сетевой smoke-тест EXE относится к первоначальной сборке; новая сетевая проверка изменения выполнена на исходниках.

## Проверено

- 516 автономных тестов; новые проверки воспроизвели перезапись ручных настроек и неправильный рабочий каталог EXE до исправлений.
- Все 25 модулей основного пакета присутствуют внутри EXE, вместе с WinDivert/winws и данными. Встроенные конфигурация и профили совпадают с чистыми шаблонами; оценок стратегий и привязок пользовательских сетей в сборке нет.
- `--help` и `--status` завершаются с кодом 0. EXE читает внешний `config.ini`, даже если запускается из другой рабочей папки. Просмотр статуса не меняет этот файл.
- `--test` запускает отдельный прокси на свободном порту, выполняет запросы и останавливает его. После завершения порт закрыт. Значения системного прокси, DNS и TTL до и после проверки совпали.
- Синтаксис основного пакета и новых скриптов совместим с Python 3.8. Фактический запуск выполнен на Python 3.11.9.

Команда проверки EXE: `python tests/smoke_frozen.py dist/Flowery.exe --network`. Она использует временную папку и не включает системные настройки.

## Сетевой результат и ограничения

Встроенная экспресс-проверка получила успешные ответы Discord Web, YouTube и Cloudflare DNS. Discord Gateway/CDN вернули HTTP 404/403, голосовые HTTP-хосты — 520. Эти ответы подтверждают получение ответа, но не загрузку медиа или голосовой сеанс. UDP-проба получила ответ; звонок Discord не проверялся.

Discord Status, X и RuTracker завершились таймаутом, NTC Party — ошибкой. Тестовый URL googlevideo вернул 404 и не доказывает воспроизведение видео. Диагностика читает только начало тела ответа; полной загрузкой эти проверки не являются. Её таймаут около 10 секунд также короче ожидания зависшего маршрута в прокси. Нужна проверка повторных запросов и обычной работы приложений.

Полный запуск с правами администратора, применение и восстановление DNS/прокси, работа трея и UDP-помощника в пользовательской сессии не проверены на готовом EXE: сеанс инструментов не имеет повышенных прав и доступа к рабочему столу. Контракты восстановления покрыты автономными тестами с подменёнными системными вызовами.

Перед публикацией остаётся пользовательская проверка обычной сессии и остановки, а также ранее отмеченные вопросы шлюза логов и отзыва старого токена. Аварийный `stop.bat` и остальные открытые замечания перечислены в [статусе аудита](audit-fixes-v1.3.0.md). Публикация — только по отдельной команде.
