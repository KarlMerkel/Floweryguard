# Исправления после аудита v1.3.0

Проверка продолжена с `61601ae`. Незавершённые изменения DNS, TTL/MTU и системных таймаутов проверены и доведены до тестируемого состояния. Версия остаётся 1.3.0.

## Исправлено

- **Запуск и служебные команды (A01):** конструктор больше не меняет системный прокси, DNS, TTL и таймер Windows. Настройки применяются при запуске служб. У `netsh/ipconfig` появились таймауты, при установке DNS отключена повторная проверка `netsh validate`, которая задерживала запуск. Суммарный дедлайн всех этапов запуска пока не введён.
- **Безопасность обычного запуска (A02/A03):** занятый порт возвращает ошибку, произвольный PID не завершается; повторный запуск не убивает предыдущую копию. `start.bat/menu.bat` не отключают пользовательский прокси до старта и после выхода. Аварийный `stop.bat` в это исправление не входит.
- **Повторный откат (A04):** неудачный возврат DNS/MTU сохраняет исходные значения. DNS-снимок записывается до изменения; при невозможности сохранить его изменение пропускается. Таймаут MTU считается неопределённым результатом и оставляет возможность отката. Cleanup сообщает о неудаче и допускает повторную попытку, включая повторный вызов при выходе. DNS-снимки учитывают `FLOWERY_HOME`. Полное восстановление TCP timestamps и сохранение TTL/MTU/прокси между аварийными завершениями остаются отдельной задачей.
- **Восстановление после сна (A05):** операции восстановления сериализованы, остановка отменяет будущие операции и ждёт выполняющуюся последовательность до отката настроек. Периодическое ожидание монитора прерывается событием остановки. Монитор запускается после готовности прокси. Реальный сон/гибернация на этой машине не проверялись.
- **Первый пакет CONNECT (A06):** ClientHello собирается через несколько TLS records с лимитом размера и времени; байты сохраняются. Короткий полученный запрос вне TLS не ждёт обязательных девяти байт. Протоколы с приветствием сервера до первых байтов клиента требуют отдельной доработки.
- **Целостность HTTP (A07):** изменение Host ограничено заголовками, тело запроса не меняется.
- **Запрет техник (часть A08):** ограничения `tcp_split/tls_record_frag/oob_data` проверяются для специальных веток выбора, ручной стратегии и третьей попытки со сменой IP. Общая политика `only_target_domains`, внешнего winws и фиксации стратегии на всех попытках ещё требует объединения.
- **Пользовательский DNS (A09):** сохранённые URL/IP используются фабрикой резолверов и harvester; смена настройки обновляет оба объекта и сбрасывает кэши прокси. Пункт выключения пользовательского DNS не означает полного выключения встроенного DoH.
- **Срок опроса DNS (часть A10):** harvester использует собственный таймаут 3 секунды и общий дедлайн ожидания 3,5 секунды, возвращает независимый снимок результатов. Сквозной бюджет CONNECT и ограничение общего количества DNS-потоков пока не реализованы.
- **IPv6 (A13):** отключение применяется к кандидатам ОС, кэшам и резервным адресам; IPv6-литералы при запрете не подключаются.
- **Fake SNI (A16):** при отказе инъекции настоящий ClientHello отправляется напрямую. Ошибка его частичной отправки не приводит к повтору того же сообщения.
- **Передача TLS (A11):** туннель неблокирующий, с ограниченными буферами в обе стороны: клиент, который не читает ответ, не останавливает передачу запроса. Ответ, замерший без данных или на объёме 6–32 КБ, закрывается через время ожидания прокси (не менее 15 с), чтобы клиент повторил запрос по другому адресу. Соединение с завершённым ответом остаётся доступным для keep-alive до 300 с.
- **Штрафы адресов (A12):** сбои подключения и зависания понижают приоритет только маршрута «сеть, хост, порт, IP» на 45 с, а не банят IP глобально. Адреса из DNS кэшируются отдельно для каждой сети. Для доменов Cloudflare после зависания адресов из DNS пробуются узлы Cloudflare той же /16, через которые в этой сети уже прошли данные, и проверенный узел `162.159.136.232`.
- **Выбор стратегии (A08, остаток):** закреплены только `direct` для игр и Telegram, режим строгого whitelist и ручная стратегия при выключенном автоподборе; они действуют на всех попытках. При внешнем winws первая попытка идёт без десинка Flowery, а Fast-Fallback переходит к собственному обходу. Для YouTube, Discord, whitelist и крупных заблокированных сайтов жёсткие правила заменены устойчивым выбором по накопленным наблюдениям без случайной разведки. Затухшие оценки без наблюдений больше не выглядят лучше проверенной техники, `direct` выбирается последним. После сбоя `combo` на том же адресе медиа Discord получает другую совместимую технику.
- **Синтетические пробы (часть A17):** калибровка и фоновые TLS-пробы не меняют оценки стратегий: успешное рукопожатие не доказывает загрузку.
- **Сохранение оценок (A18):** записи одного движка сериализованы, временные файлы имеют уникальные имена; при ошибке dirty-флаг сохраняется и запись можно повторить сразу. Атомарная запись config и профилей остаётся открытой.

- Итоговый автономный набор после этапа транспорта и маршрутов: **507 тестов, OK**; интеграционная проверка TLS 1.3 через локальный прокси — OK. Живая проверка через изолированный экземпляр с копией оценок пользователя: Discord, YouTube, i.ytimg.com, RuTracker, GitHub загружаются полностью; keep-alive туннель переиспользуется после 20 с простоя; X и Surfshark после первого зависания (около 16 с) загружаются полностью через другой узел. «Дождь» (собственный хостинг) и SoundCloud (CloudFront) обрываются на всех проверенных адресах.
- Предыдущий итог: **499 тестов, OK**; исходный набор до этой работы — 476. Проверка шлюза: **2 теста, OK**. Компиляция исходников и тестов проходит; Python 3.8 проверен по синтаксису, запуск выполнен на Python 3.11.9.
- Новые контракты находятся в `test_system_recovery_contract.py`, `test_audit_transport_contract.py`, `test_runtime_settings_contract.py`, `test_safe_startup_contract.py`. Они воспроизводили ошибки до исправлений. Сборка ClientHello дополнительно проверена настоящими локальными сокетами.
- В тестовый запуск добавлены запреты прямых неподменённых записей через winreg и изменяющих команд netsh/reg/sc/taskkill. Проверки выполняются во временной копии; внешняя сеть запрещена.
- Старые проверки обновлены под новое поведение: отсутствие произвольного завершения процессов, отсутствие сброса чужого DNS, новое поле политики стратегий в подмене. Утверждения не удалялись ради зелёного результата.

- Основные изменения синхронизированы в `Flowery_Release/Floweryguard`. Это локальная копия исходников, не опубликованный выпуск.

## Открытые вопросы

Полный список и исходные доказательства — в [аудите](full-audit-v1.3.0.md). Прежде всего остаются:

1. Перезапись пользовательских переключателей профилем (A14). Первое зависание на новом адресе по-прежнему стоит около 15 с, пока маршрут не будет понижен.
2. Обрыв передачи на всех адресах хоста (собственный хостинг, CloudFront) сменой адреса не обходится.
3. Навязанный HTTP→HTTPS и повторное использование HTTP-соединения (A15).
4. Калибровка, завершение фоновых потоков/меню, диагностика и приватность отчётов (A17/A19–A22).
5. Аварийный `stop.bat`, владение внешним winws и полноценное восстановление после аварии (остаток A02/A03/A04).
6. Воспроизводимая сборка, неподключённые настройки и Win32/WinDivert-сценарии (A23 и раздел дополнительной проверки).

Доступность проблемных сайтов в живой сети этой серией автономных проверок не подтверждается. EXE не пересобирался, публикаций и отправки логов не было.
