# Повторные обрывы Discord: проверка 28 октября 2026

- На присланных снимках отсутствуют превью трансляции и часть аватарок.
- Последний пользовательский лог `Flowery_v1.3.0_2026-10-27_18-43-05.log`
  содержит 29 сообщений о зависании `cdn.discordapp.com` на восьми адресах,
  с 18:44 до 20:34. Это не только первоначальный подбор при запуске.
- Сохранённый результат предыдущей проверки `scratch/discord-deep-matrix.json`:
  из 11 адресов с `combo_tlsrec_tcpsplit` один передал файл целиком,
  остальные остановились после 12–17 КБ. Прямое подключение в той проверке
  не завершило TLS ни на одном из 11 адресов. Проверка выполнялась через
  сокет и SSL MemoryBIO, вне пересылки прокси.
- В текущем прогоне до истечения ссылки тот же файл полностью получен
  на четырёх адресах с тремя техниками (`direct`, `combo_tlsrec_tcpsplit`,
  `tls_record_frag`): 12 из 12 запросов, 0,235–0,547 секунды.
  Во всех случаях HTTP 200, 994 912 байт, SHA-256
  `0e3a1e6340727ae53c8e09ace76208b95c9912f69b01163ba4e0d8b68160e1f0`.
  Несмотря на расширение GIF, сервер отдаёт `image/png`.
- При последующей проверке через изолированный прокси ссылка уже истекла
  (28 октября, 06:37:28 UTC+3). HTTP/1.1 и HTTP/2 вернули тело ошибки 404
  на 36 байт. Это **не** успешная проверка файла через исправленный прокси.

Разница сетевых результатов не позволяет приписать сегодняшнюю доступность
исправлению. Причину изменения условий сети не установили. По прежним
данным зависимость от маршрута подтверждается; конкретный механизм
сетевого ограничения без дополнительных измерений не установлен.

## Воспроизведённый дефект и исправление

Порядок попыток адресов сохранялся 300 секунд, а неудачная техника для пары
хост/IP — только 45 секунд. При 11 адресах и 15 секундах ожидания круг
занимает 165 секунд. К следующей попытке первого адреса селектор забывал
неудачную технику и снова выбирал её.

Тест `test_full_address_sweep_does_not_forget_failed_technique` воспроизвёл
повтор `combo_tlsrec_tcpsplit` до исправления. Теперь наблюдение о технике
живёт 300 секунд, как память порядка попыток. Понижение приоритета самого
IP по-прежнему действует 45 секунд. Адрес не запрещается; наблюдение
ограничено сетью, хостом, портом и IP. Ручной выбор не переопределяется.
Успешное наблюдение той же техники заменяет подозрение; данные истекают
и ограничены размером кэша.

В журнал добавлены адрес, техника и сеть при начале TLS-передачи, а также
объёмы, длительность, причина завершения и оценка при её окончании.
Полные URL, подписи вложений и содержимое запросов не записываются.

## Проверки и границы результата

- 565 автономных тестов прошли во временной копии проекта, включая
  контракты маршрутизации и явных пользовательских настроек.
- После добавления журнала повторно прошли 8 тестов передачи TLS.
- Основной и локальный релизный экземпляры изменённых модулей синхронизированы.
- Новая локальная сборка находится в `dist/Flowery-v1.3.0-portable`.
  Опубликованный релиз и тег не изменялись.

Это исправление одного подтверждённого дефекта адаптации. Оно не доказывает
восстановление всех аватарок, превью и вложений Discord. Первоначальное
ожидание каждого зависшего подключения остаётся; новое соединение должен
открыть клиент. TLS-прокси не видит границы HTTP/2-запросов и не может
безопасно перенести уже начатый зашифрованный запрос на другой адрес.
Порог 64 КБ подтверждает лишь объём передачи, а не полноту ответа.

Для следующего воспроизведения важны лог новой сборки, время сбоя и
действующая ссылка. Строки `[TLS-маршрут]` позволяют сопоставить начало,
завершение и технику по имени потока без предположений о выбранном адресе.
