# Ожидание подбора TLS-маршрута

После обычных попыток Fast-Fallback Flowery продолжает подбор в исходном
соединении браузера. Дополнительные попытки используют остаток 15 секунд,
отсчитываемых с начала TLS-подбора. Они используют адреса текущей сети из
DNS-кэша и первоначальный адрес, выбирая техники по наблюдениям. Ручные
адреса, ручная стратегия и запрет IPv6 сохраняются.

Повтор допускается только для полного ClientHello, включая его разбиение
на несколько TLS-записей и необязательный ChangeCipherSpec. Данные приложения,
предложение TLS 0-RTT, неполное сообщение или новые байты клиента запрещают
дополнительный повтор. До первого ответа сервера браузеру не отправляются
фиктивные данные для продления ожидания. После ответа начинается обычная
пересылка; сменить сервер внутри уже установленного TLS-сеанса нельзя.

Ожидание дополнительного TLS-ответа прерывается при закрытии страницы,
остановке прокси или смене сети. Операции TCP-подключения и отправки имеют
собственные короткие таймауты. Награда за успешную загрузку не начисляется
за один ответ рукопожатия. В журнал добавлены события `[TLS-ожидание]`.

Ограничения: собственный таймаут браузера остаётся в силе. Отсчёт не включает
начальное разрешение DNS, установление CONNECT и чтение ClientHello.
Неисправный маршрут после начала передачи по-прежнему требует нового
подключения клиента. Если новых сочетаний адреса и техники нет, подбор
заканчивается раньше предела ожидания.

Проверки: `python tests/run.py` — 632 теста прошли. Проверки на локальных
сокетах подтверждают получение ответа после трёх неудачных попыток без
закрытия клиентского сокета, сохранение ClientHello, ограничение времени,
отмену ожидания, запрет повтора данных приложения и соблюдение ручного выбора.
Работа в реальном браузере и ускорение Discord в текущей сети не измерялись.
