# Причина неполной загрузки страниц — 27 октября 2026

## Что проверено

Открыты все шесть скриншотов: Canva, Charter97, Discord, Meduza, NordVPN, Signal. Журнал `Flowery_v1.3.0_2026-10-27_01-34-57.log` подтверждает запуск `dist/Flowery-v1.3.0-portable/Flowery.exe`, профиль `home_wifi`, сеть `gw:192.168.3.0/24`. В момент снимков записаны зависания ресурсов после первых килобайт. Сессия штатно остановлена в 01:37:07.

Выполнено 150 контрольных запросов: исходные HTML и ресурсы напрямую/через прокси, 49 проверок семи техник на одинаковых IP, 24 контрольных сравнения адресов, повтор через исправленные исходники, HTTP/2 и запуск с копией пользовательского состояния. Дополнительно выполнена встроенная сетевая проверка готового EXE. Проверка TLS-сертификата включена. Настройки, оценки и привязки сети пользователя не сбрасывались; хэши исходных файлов переносимого комплекта после проверки совпали. Активный маршрут — физический Realtek через `192.168.3.1`; процессов Flowery/winws во время сравнений не было.

## Основная подтверждённая ошибка

`flowguard/proxy.py:is_bogon_or_sinkhole_ip()` безусловно отбрасывал **все адреса `8.6.112.0/24` и `8.47.69.0/24`** как «заглушки провайдера». Это неверно для текущей сети: системный DNS возвращает их для ряда сайтов, они предъявляют подходящий доверенный сертификат и полностью отдают запрошенные файлы. Старый тест даже требовал отклонять эти адреса, поэтому зелёный набор не обнаруживал дефект.

После отбрасывания рабочих адресов Flowery получал другие через DoH и подключался к ним. Кроме того, для всех доменов списка обхода DoH безусловно ставился впереди системных ответов даже без пользовательского выбора DNS. На части этих маршрутов TCP и TLS проходили, но тело ответа переставало поступать. Это объясняет HTML без оформления, отсутствующие скрипты и белые страницы.

Контрольные запросы **вне транспортного кода Flowery**, с тем же хостом, путём и техникой:

| Ресурс | Полная загрузка | Проблемный адрес |
|---|---|---|
| Signal, `bulma-1.0.4.min.css` | `8.6.112.0`: 677 931 байт, direct и combo | `104.18.10.47`: 18 327/14 226 байт, затем таймаут |
| Localize, `localize.js` | `8.47.69.0`: 86 782 байта, direct и combo | `104.18.0.42`: 18 345/17 775 байт, затем таймаут |
| Meduza, HTML | `8.6.112.0`: 454 219 байт с combo | `104.18.1.79`: 17 997 байт с combo, затем таймаут |
| Canva, `/restricted-access/` | `8.6.112.0`: полный **HTTP 403**, 754 746 байт с combo | `104.16.102.112`: 11 619 байт того же HTTP 403, затем таймаут |

Полный HTTP 403 не означает доступ к сервису. Принадлежность конкретного промежуточного устройства, вызывающего обрыв на проблемных маршрутах, этим экспериментом не установлена. Однако обрыв воспроизводится без пересылки Flowery — общий лимит буфера прокси в 16 КБ его не объясняет. Прежнее объяснение только выбором TLS-техники было неполным: сравнивались также разные маршруты.

## Исправления

- Убран необоснованный запрет двух публичных подсетей. Новые IP не добавлены в жёсткий список рабочих адресов. Фильтрация loopback, частных диапазонов и Fake-IP сохранена.
- В автоматическом режиме валидные системные DNS-ответы сохраняют начальный порядок, DoH добавляет альтернативы. При явно включённом пользовательском DNS его ответы имеют приоритет. Наблюдения о передаче по-прежнему влияют на выбор адреса.
- Исправлен независимый дефект обратной связи: успешная передача через `direct` теперь обучает селектор, как и другие техники. Ранее вызов `record_success` для неё пропускался.

Изменения малы и не закрепляют технику за сервисом. Основная и локальная релизная копии синхронизированы.

Для шести доступных напрямую ресурсов совпали также хэши прямой загрузки и исправленного прокси. Это проверка байтов ресурсов, а не полной отрисовки страниц, авторизации или всех динамических зависимостей.

**538 автономных тестов прошли.** Новые регрессии воспроизвели запрет публичных IP, неправильный порядок источников DNS и отсутствие обучения `direct` до исправления. Явный выбор DNS и фильтрация Fake-IP проверены отдельно. EXE пересобран; справка, статус и чтение внешнего конфигурационного файла прошли без изменения системного прокси/DNS/TTL.

`python tests/smoke_frozen.py dist/Flowery-v1.3.0-portable/Flowery.exe --network` завершился с кодом 0: подтверждены запуск отдельного прокси, его остановка, закрытие порта и неизменность системных настроек. Это **не** успешный тест всех сайтов: Discord Status, X и RuTracker дали таймаут, NTC Party — ошибку; Discord Web и YouTube ответили. HTTP 404/403/520 диагностических URL Discord не доказывают загрузку медиа или голосовой сеанс. Отдельная UDP-проба осталась без ответа — причину отсутствия ответа и работоспособность звонков она не устанавливает.

## Что остаётся

Нельзя объявлять все страницы исправленными или выпуск готовым. Остаются неполные ответы Canva/NordVPN, первая неудачная попытка отдельных CDN-ресурсов и серверные HTTP 403. Перебор большого числа IP может задерживать смену техники; долговременные доменные оценки всё ещё переносят часть наблюдений между адресами. Эти ограничения не устраняются возвратом запрещённых подсетей и требуют отдельной проверки. РБК, SoundCloud и «Дождь» в этом этапе заново не проверялись.

Диагностика сохранена локально в `scratch/web-audit/`, `scratch/web-audit-fixed/`, `scratch/web-audit-user-state/`; исходные пользовательские логи и тела ответов не включены в Git. Публикаций и отправки логов нет. Предыдущие EXE вне `dist` не заменены.
