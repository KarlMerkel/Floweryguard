Локальная проверочная сборка после опубликованной 1.3.0. Тег и GitHub Release не менялись.

## Использование

1. Завершить прежний Flowery через `0` или `Ctrl+C`.
2. Запустить `C:\Users\egor8\Downloads\Flowery-diagnostics-2026-10-29-logs\start.bat`.
3. Открыть **19 — Живой журнал соединений** и повторить проблемное действие.
   Журнал открывается в отдельном окне, основное меню остаётся доступным.
   Закрытие окна журнала или Ctrl+C в нём не останавливает службы.
4. Для ошибки сертификата выбрать **20 — Проверить сертификат сайта**, ввести
   только домен, например `animego.me`. Проверка сравнит прямое соединение
   с соединением через работающий прокси.

Комплект отдельный. Рабочий каталог `Flowery-v1.3.0-portable`
не заменялся. Программа по-прежнему сообщает версию 1.3.0; конкретную локальную
сборку отличают `BUILD_INFO.json` и `SHA256SUMS.txt` рядом с EXE.

Обновление с отдельным окном журнала собрано на C:.
SHA-256 проверенного EXE:
`2674adebba71757b7ab90c3819fde2b2abf91ea0ab24f7a9865720410b3c9799`.

Его настройки и оценки при наличии скопированы в новый комплект.

Окно журнала — отдельный процесс, читающий файл текущей сессии. Повторный выбор
пункта 19 не создаёт дубликатов. После закрытия журнал можно открыть снова.
Просмотрщик не импортирует службы, не запрашивает UAC и не регистрирует откат
системных настроек. Он продолжает показывать журнал после остановки основного
процесса, пока пользователь не закроет окно.

## Подробный журнал

- Миллисекунды и `conn=…` связывают события одного клиентского соединения.
- Для CONNECT записываются хост, порт и время получения TCP-соединения.
- Для каждой TLS-попытки: IP, техника, номер попытки, TCP RTT, разрешённое время
  ожидания, фактическое ожидание, результат и размер первого ответа.
- Для передачи: отправленные/полученные байты, длительность, причина завершения,
  незавершённость TLS-записи и локальная оценка маршрута.
- Объём первой порции TLS показан отдельно. HTTP внутри туннеля не расшифровывается;
  его полнота явно обозначена как неизвестная.
- Отдельное окно начинает с последних 200 строк в пределах хвоста 64 КиБ,
  затем читает новые записи порциями до 64 КиБ. Сетевые потоки не пишут в эту
  консоль; её медленный вывод не задерживает передачу данных.
- Новая трассировка не добавляет тело запроса, cookies или параметры подписанных ссылок.
  Домены и IP присутствуют: журнал содержит сведения о посещаемых ресурсах.

## Исправления аудита

- **N01/N07:** в рабочем прокси отключён ShadowProber, не завершавший жизненный цикл
  и начислявший успех за 16 байт синтетического ответа. Оставшаяся вспомогательная
  проба не начисляет наград и проверяет разрешённую технику. Калибровка сохранена.
- **N02:** таймаут/RST больше не превращается автоматически в доказательство ТСПУ
  и сильный штраф домену/CDN. Ожидание TLS учитывает запас на обработку сервером,
  отдельно от TCP RTT и в пределах остатка бюджета. Проверен ответ через 650 мс
  на настоящих локальных сокетах; прежняя реализация закрывала его раньше.
- **N03:** результаты неудачных TLS-попыток, включая первую и последнюю,
  сохраняются по исходной сети, хосту, порту, IP и технике. Успешный запасной
  адрес не стирает отказ предыдущего. Постоянных списков плохих IP не добавлено.
- **N04:** убрана классификация зависания по диапазону 6–32 КиБ. Поток отслеживает
  границы TLS-записей, сохраняя только до пяти байт заголовка и оставшуюся длину.
  Законченные короткие записи не понижают оценку из-за простоя. Незавершённая
  запись замечается и после 64 КиБ; ранняя передача большого объёма больше не
  начисляет немедленную долговременную награду. Награда возможна при завершении
  соединения без обнаруженного обрыва, но по-прежнему не доказывает успех HTTP.
- **N05:** изменение отпечатка сети вызывает callback и при неизменном профиле.
- **N08:** штатный источник заменён на список в `KarlMerkel/Floweryguard/main`.
  Загрузка ограничена 1 МиБ, строки проверяются как домены. Файл заменяется
  атомарно, с резервной копией; отказ записи сохраняет старую базу.

## Проверки

- `python tests/run.py`: **594 теста**, без внешней сети и изменения пользовательских файлов.
- Проверки TLS: задержанный первый ответ, разбитый заголовок, частичная запись
  после большой передачи, завершённый маленький ответ, half-close и противодавление.
- Проверки журнала: ограниченная память, удаление управляющих символов,
  освобождение контекста соединения, выход из просмотра, вывод пунктов широкого меню.
- Диагностика сертификата проверена на ошибке доверия, имени сайта и HTTP CONNECT.
  Ни один путь не отключает проверку TLS и не повторяет запрос с непроверенным сертификатом.
- Готовый EXE: `tests/smoke_frozen.py` проверил справку, статус и чтение внешнего
  конфига, а также режим `--log-window … --once` без видимого окна. Он прочитал
  журнал и не создал/изменил файлы сессии. Снимки системного прокси, TTL и DNS до/после совпали. Запуск всех служб
  с UAC и управление меню на рабочем столе не проверялись.
- В текущей сети `animego.me` напрямую предъявил проверенный сертификат Let's Encrypt,
  действующий до 18 декабря 2026. Это не объясняет прежнюю ошибку на другом ПК.
- Тестовая аватарка Discord: HTTP 200, 1268 байт напрямую и через изолированный
  прокси, SHA-256 совпал. HTML Signal: HTTP 200, 22194 байта, чтение до завершения
  в обоих режимах; хэши страниц различаются, побайтовое совпадение не заявляется.
  Первый запрос со стандартным User-Agent Python получил 403; повторное сравнение
  выполнено с одинаковым браузерным User-Agent.
- Действующий источник списка проверен отдельно: HTTP 200, 402 домена.
- Первый сетевой скрипт оставил временную копию из-за открытого лог-файла.
  В повторном скрипте обработчики закрываются перед удалением. Отдельное удаление
  старой копии `Temp/flowery-diag-check-956it4lr` отклонено автоматической проверкой
  (`blocked by policy`); эта копия могла остаться на диске.

## Границы и следующие задачи

### Обновление активного маршрута, 30 октября

Во время длинного TLS-соединения наблюдение о рабочем маршруте раньше записывалось
только один раз и через пять минут истекало, несмотря на продолжающуюся загрузку.
Теперь оно обновляется по новым доставленным данным: не чаще раза в 30 секунд,
после дополнительных 64 КиБ и на границе полной TLS-записи. Простой не продлевает
наблюдение. Повторное обновление не начисляет награду стратегии; она по-прежнему
учитывается отдельно при завершении соединения.

Проверено 599 автономными тестами, включая длительную передачу с моделируемым
временем, простой, неполную запись и отсутствие повторных наград. Исправление
сохраняет найденный маршрут; ускорение первого подключения и время загрузки
реального Discord этим тестом не измерены.

- Если HTTP-ответ оборвался ровно между законченными TLS-записями, прокси не может
  отличить это от нормального keep-alive без клиентской диагностики. Отсутствие
  неполной TLS-записи не является доказательством полного файла.
- **N06 остаётся:** отпечаток по SSID/подсети шлюза недостаточно различает сети.
  Полная миграция идентичности сети и результатов уже начатых асинхронных операций
  в этом этапе не выполнена.
- Проверки не воспроизводят сеть пользователя из логов 28 октября. Устранение
  всех зависаний Discord, превью, звонков и прочих сайтов не подтверждено.
- `tg-ws-proxy` изучен по [документации](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/EN/README.md)
  и [зависимостям](https://github.com/Flowseal/tg-ws-proxy/blob/main/pyproject.toml):
  MTProto → WebSocket, MIT, зависимости `cryptography`, `httpx` и другие.
  Прямое включение нарушает правило Flowery «только стандартная библиотека».
  Внешний помощник либо собственная реализация требуют отдельного выбора;
  библиотек/сторонних EXE в комплект не добавлено. Поддержка звонков в прочитанной
  документации не подтверждена; её нельзя выводить из работы MTProto-сообщений.
- Для игровой проблемы пока неизвестны игра и точный этап отказа.
- Отправка отчётов по нестабильной сети и политика watchdog при ручном отключении
  системного прокси в этом этапе не менялись.
