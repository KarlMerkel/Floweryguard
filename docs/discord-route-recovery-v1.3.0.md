# Повторный сбой вложений Discord — 27 октября 2026

## Причина и изменение

После зависания передачи адрес получал статус `suspect` на 45 секунд.
Проверка нескольких следующих адресов занимала больше этого времени:
ранние неудачные адреса снова становились неизвестными и возвращались
в начало очереди. До рабочего кандидата перебор мог не доходить.

Контрольное сравнение на одинаковой очереди из пяти адресов воспроизвело
цикл: прежний порядок после четырёх обрывов повторил первые два адреса.
Исправленный порядок на пятой и шестой попытках получил PNG целиком
(594 274 байта). Это сравнение сохранено в локальном
`scratch/discord-route-recovery-long.json`.

Теперь после подозрения на зависание порядок проб учитывается пять минут.
Среди адресов с одинаковым состоянием неизвестные, ещё не проверенные узлы
предшествуют недавно испробованным. Наблюдавшаяся передача данных имеет
приоритет. Успешное TCP-подключение само по себе не запускает ротацию.
Состояние ограничено сетью, хостом и портом, имеет срок действия и лимит
числа записей. Новых фиксированных IP и TLS-стратегий нет.

Исходники и локальная копия `Flowery_Release/Floweryguard` синхронизированы.
Исправление и четыре регрессионных теста: коммит `b22213d`.

## Проверки

`python tests/run.py`: 563 теста прошли, включая четыре теста ещё
незавершённой подготовки архивов выпуска. Тесты выполнялись в изолированной
копии; обязательные проверки правил маршрутизации входят в общий набор.

Все четыре присланных вложения скачались по HTTP/1.1 в предыдущем

## Ограничения

- Поиск рабочего маршрута при холодном старте всё ещё требует нескольких
  запросов и может занимать около двух минут. Исправлен цикл перебора,
  но мгновенная загрузка при первом обращении не обеспечена.
- Прокси не может перенести уже установленный TLS-сеанс на другой IP:
  нужен новый запрос клиента. Отображение вложений в самом Discord
  после перезапуска здесь не проверялось.
- Встроенная проверка EXE вернула таймауты Discord Web, X и RuTracker.
  Ответы `403/404/520`, помеченные диагностикой как `TLS OK`, не являются
  доказательством работоспособности сервиса.
- Подготовка релиза приостановлена; её незавершённые файлы сохранены в
  рабочем дереве отдельно от исправления. Выпуск не опубликован.
