# Flowery (Glue) 1.3.0

Flowery — приложение для Windows, которое помогает открывать сайты и сервисы, соединения с которыми ограничивает DPI или мобильный оператор. Оно запускает локальный HTTP/HTTPS-прокси и автоматически подбирает способы передачи для вашей сети.

**Последний выпуск: [Flowery 1.3.0](https://github.com/KarlMerkel/Floweryguard/releases/tag/v1.3.0)** · [Все выпуски](https://github.com/KarlMerkel/Floweryguard/releases)

## Установка

1. Скачайте архив **Windows x64** со страницы [выпуска 1.3.0](https://github.com/KarlMerkel/Floweryguard/releases/tag/v1.3.0).
2. Распакуйте его в папку, доступную для записи.
3. Запустите `start.bat` и разрешите запрос администратора, если Windows его покажет.
4. Выберите нужные параметры в меню. Для обычного выхода используйте пункт `0` или `Ctrl+C`.

Для запуска готового Windows-комплекта Python не нужен. При работе из исходников требуется Python 3.8 или новее; основной код использует стандартную библиотеку Python.

## Что нового в 1.3.0

- Переработан адаптивный выбор маршрутов и стратегий обхода. Flowery учитывает результаты соединений в вашей сети и сохраняет оценки для последующего выбора.
- Улучшены переключение между адресами и стратегиями при зависаниях и ошибках передачи.
- Добавлены защищённый DNS внутри прокси, настройка DNS-сервера и управляемое использование пользовательского `hosts.txt`.
- Добавлены быстрая и полная калибровка, расширена база целевых доменов.
- Улучшены профили сети и сохранение ручных настроек.
- Добавлены восстановление работы после сна, настройка MTU и выборочная блокировка QUIC.
- Обновлены диагностика, меню, сборка Windows и проверка SHA-256.

Полный список изменений — в [описании выпуска 1.3.0](https://github.com/KarlMerkel/Floweryguard/releases/tag/v1.3.0).

## Адаптация к сети

При работе Flowery накапливает результаты соединений и использует их при следующих попытках. Чем больше наблюдений собрано в вашей сети, тем больше данных доступно для выбора маршрута и стратегии. После смены сети или на первом запуске подходящий маршрут может искаться дольше; например, Discord в одной из проверок восстановил загрузку примерно через 1–2 минуты.

Обучение помогает адаптировать выбор, но не гарантирует доступность каждого сайта. Результаты зависят от оператора, сети и доступности серверов.

## Как это работает

- Локальный HTTP/HTTPS CONNECT-прокси доступен по адресу `127.0.0.1:8118`. Приложения используют его через системные настройки Windows или собственную настройку прокси.
- Для TCP доступны разделение TLS ClientHello, фрагментация TLS-записей и обработка HTTP-заголовка Host. В автоматическом режиме Flowery может менять стратегию по результатам соединений.
- Прокси поддерживает DoH и резервные DNS-резолверы.
- Профили помогают выбрать настройки для мобильной раздачи, Wi-Fi и других сценариев.
- Дополнительные функции Windows включают настройку TTL/MTU и выборочную блокировку QUIC.
- Для Discord Voice предусмотрен отдельный UDP-помощник на базе компонентов WinDivert и `winws.exe` из `zapret_bin`. Он не нужен для работы основного TCP-прокси.

## Ограничения

- Flowery не является VPN и не меняет внешний IP-адрес.
- Через Flowery проходят приложения, использующие системный прокси, и приложения, в которых прокси настроен явно. Не каждое приложение учитывает системную настройку Windows.
- Отказ сайта по региону, авторизации, антибот-проверке или HTTP 403 не обязательно связан с DPI и может не устраняться прокси.
- HTTPS-трафик проксируется без расшифровки. Поэтому Flowery не может проверить, что приложение получило и обработало каждый байт ответа.
- Настройка DNS, TTL, брандмауэра и WinDivert требует прав администратора. Эти функции меняют системные параметры Windows.

## Профили и настройки

Настройки находятся в `config.ini`, профили — в `network_profiles.json`. В комплекте предусмотрены профили:

| Профиль | Для чего |
| --- | --- |
| `tethering` | Раздача мобильного интернета |
| `home_wifi` | Домашняя сеть и Wi-Fi |
| `strict_whitelist` | Обход только для доменов из `whitelist.txt` |
| `clean_gaming` | Игровой сценарий |

Ручные настройки пользователя имеют приоритет над значениями профиля. Список доменов в `whitelist.txt` используется согласно настройке `only_target_domains`; сам по себе он не включает ограничение трафика только этим списком.

## Запуск из исходников

Чтобы получить исходники именно версии 1.3.0, клонируйте репозиторий и переключитесь на тег выпуска:

```powershell
git clone https://github.com/KarlMerkel/Floweryguard.git
cd Floweryguard
git checkout v1.3.0
```

Откройте PowerShell в каталоге проекта:

```powershell
python flowguard/main.py
```

Основные команды:

```powershell
python flowguard/main.py --help
python flowguard/main.py --all
python flowguard/main.py --all --profile tethering
python flowguard/main.py --status
python flowguard/main.py --detect
python flowguard/main.py --test
python flowguard/main.py --calibrate quick
python flowguard/main.py --calibrate full
python flowguard/main.py --clean
```

`--test` проверяет доступность сайтов через прокси и использует внешнюю сеть. `--clean` сбрасывает сетевые настройки Flowery; используйте его осознанно.

## Сборка и тесты

Для запуска из исходников и автономных тестов внешние Python-пакеты не нужны. Для сборки EXE потребуется PyInstaller:

```powershell
python -m pip install PyInstaller==6.22.3
python build_local.py
```

Запуск автономного набора:

```powershell
python tests/run.py
```

Сборка и автономные тесты не проверяют доступность сайтов у конкретного оператора. Сетевая проверка зависит от текущего подключения.

## Проверка загрузки

Выпуски содержат SHA-256 для файлов. В PowerShell проверьте скачанный файл так:

```powershell
Get-FileHash .\Flowery.exe -Algorithm SHA256
```

Сверьте полученное значение с файлом контрольных сумм в соответствующем выпуске. Загружайте программу только из [официального репозитория](https://github.com/KarlMerkel/Floweryguard).
