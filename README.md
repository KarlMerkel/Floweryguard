# Flowery (Glue)

Flowery — инструмент для Windows 10/11, который помогает обходить DPI-блокировки через локальный прокси и настраивать подключение при раздаче интернета с телефона. Текущая разрабатываемая версия — **1.3.0**.

Основной код написан на Python 3.8+ и использует стандартную библиотеку. Пакеты из pip для запуска не нужны. Голосовой UDP-трафик Discord обрабатывается отдельным помощником на основе `winws.exe` и WinDivert из каталога `zapret_bin`.

Репозиторий: [KarlMerkel/Floweryguard](https://github.com/KarlMerkel/Floweryguard). Название репозитория историческое; основной Python-пакет — `flowguard`.

## Запуск

Распакуйте проект в доступную для записи папку и запустите `start.bat`. Скрипт запрашивает права администратора и открывает интерактивное меню. `menu.bat` также открывает меню.

Если рядом с BAT-файлом есть исходники, скрипт ищет Python и запускает их. `Flowery.exe` используется, когда исходников нет. Наличие EXE рядом с исходниками не отменяет необходимость установить Python.

Повторный запуск не завершает работающую копию. Если порт прокси занят другой программой, Flowery сообщает об ошибке; перед перезапуском завершите предыдущий экземпляр через пункт `0` или `Ctrl+C`.

Для ручного запуска откройте терминал в каталоге проекта:

```powershell
python flowguard/main.py
```

Без аргументов открывается меню. Полный запуск без меню:

```powershell
python flowguard/main.py --all
```

Для TTL, MTU, настройки DNS, правил брандмауэра и WinDivert нужны права администратора. Обычный локальный прокси сам по себе не требует драйвера.

Завершайте работу через пункт `0` или `Ctrl+C`: приложение выполняет очистку системных настроек. `stop.bat` предназначен для принудительной остановки и сброса настроек, в том числе возврата DNS к DHCP. Это не точное восстановление произвольной ручной конфигурации Windows.

## Как работает обход

- Локальный HTTP/HTTPS CONNECT-прокси слушает `127.0.0.1:8118`. Системный прокси Windows настраивается автоматически, если включён `auto_system_proxy`.
- Для TCP используются разделение ClientHello, фрагментация TLS-записей и изменение HTTP-заголовка Host. Исторические имена OOB, overlap и padding в диспетчере сейчас являются алиасами TCP split; отдельных реализаций этих техник в рабочем пути нет.
- Адаптивный выбор стратегий использует Thompson Sampling. При неудаче прокси пробует другую стратегию или IP; результаты сохраняются в `strategy_scores.json`.
- Для TLS-туннелей первый ответ сервера ещё не подтверждает маршрут. Передача от 64 КиБ повышает приоритет адреса; признаки зависания временно снижают его для новых соединений. Наблюдения хранятся в памяти отдельно по сети, хосту и порту. Прокси не расшифровывает HTTPS и не может проверить полноту каждого ответа или перенести уже установленный TLS-сеанс на другой IP.
- Для разрешения доменов доступны DoH, резервные резолверы и пулы IP для отдельных сервисов. Резервный резолвер не переходит на UDP DNS для известных блокируемых доменов при сбое DoH. Пользовательские URL и адреса DNS применяются к резолверам прокси. `hosts.txt` не подключён к рабочему пути выбора адреса; это не системный файл Windows.
- Для мобильной раздачи предусмотрены TTL 65, TCP timestamps и настройка MTU. Поставляемое значение MTU — 1420.
- Блокировщик QUIC создаёт правила для обнаруженных браузеров и Discord, чтобы перевести соединения с UDP 443 на TCP.
- Помощник Discord Voice использует WinDivert для UDP и учитывает уже запущенный сторонний `winws.exe`. При обнаружении внешней TCP-фильтрации прокси выбирает прямую передачу, чтобы избежать повторной обработки соединения.

Flowery не является VPN и не меняет внешний IP. Через прокси проходит трафик приложений, которые используют системные настройки или явно настроены на `127.0.0.1:8118`. Работа конкретного сайта зависит от сети, доступности адресов и правил оператора; названия профилей не гарантируют обход любых ограничений.

## Меню

| Пункт | Действие |
| --- | --- |
| 1–5 | Запуск и остановка службы, выбор профиля, трей, статус, сброс настроек |
| 6–11 | TTL, QUIC, Discord, голос Discord, YouTube, автоматический выбор стратегии |
| 12 | Выбор и проверка защищённого DNS |
| 13 | Быстрая или полная калибровка стратегий |
| 14 | Диагностика сети |
| 15 | Проверка доступности сайтов через прокси |
| 16 | Открытие лога текущей сессии |
| 17 | Обновление списка доменов из сети |
| 18 | Отправка диагностического лога разработчику после подтверждения |
| 0 | Выход с очисткой настроек |

Калибровка и проверка сайтов обращаются к реальным внешним серверам. Это инструменты диагностики, а не автономные тесты исходного кода.

## Профили и настройки

Профили хранятся в `network_profiles.json`.

| Идентификатор | Назначение |
| --- | --- |
| `tethering` | Мобильная раздача |
| `home_wifi` | Домашний интернет / Wi-Fi; выбор по умолчанию для неопознанной сети |
| `strict_whitelist` | Применение обхода только к доменам из `whitelist.txt` |
| `clean_gaming` | Игровой профиль с базовой стратегией `tcp_split_sni_mid` |

Встроенные профили включают TTL и блокировку QUIC, включая `home_wifi` и `clean_gaming`. Явные значения из `config.ini` и переключатели меню имеют приоритет над профилем и сохраняются при перезапуске и смене сети. Параметры командной строки действуют до завершения программы. Чтобы снова использовать значение профиля, удалите соответствующую строку из `config.ini` при остановленной программе. При смене профиля его прежние значения не накапливаются.

| Раздел config.ini | Настройки |
| --- | --- |
| `[proxy]` | Адрес, порт, таймауты, системный прокси, Discord и YouTube |
| `[bypass]`, `[fragmentation]` | Техники обхода и размер/задержка фрагментов |
| `[tethering]` | TTL, timestamps, MTU и дополнительные настройки раздачи |
| `[quic]` | Блокировка QUIC |
| `[dns]` | Системный DNS и DoH; в поставляемом конфиге выбран Quad9 |
| `[targets]` | Список доменов, ограничение обхода и использование hosts.txt |
| `[strategy]` | Автовыбор и базовая стратегия |
| `[mode]`, `[desync]` | Режим proxy / packet / hybrid и параметры пакетного помощника |
| `[whitelist_bypass]` | Дополнительные SNI-настройки; выключены в поставляемом конфиге |
| `[support]` | Способ и адрес отправки диагностических отчётов |

Основной режим — `proxy`. Пакетная TCP-обработка зависит также от `tcp_fake_desync` и наличия WinDivert; одно изменение `mode.kind` не включает все методы автоматически.

`whitelist.txt` означает список доменов для обхода, а не разрешающий список оператора. При `only_target_domains = false` прокси работает в общем режиме. По умолчанию включена стратегия `combo_tlsrec_tcpsplit`; OOB, удаление ECH и изменение TLS padding выключены.

## Командная строка

```powershell
python flowguard/main.py --help
python flowguard/main.py --all --profile tethering
python flowguard/main.py --all --tray
python flowguard/main.py --status
python flowguard/main.py --detect
python flowguard/main.py --test
python flowguard/main.py --calibrate quick
python flowguard/main.py --calibrate full
python flowguard/main.py --all --strategy combo_tlsrec_tcpsplit --no-auto-strategy
python flowguard/main.py --clean
```

`--test` проверяет сайты через локальный прокси и при необходимости временно запускает его. `--clean` (также `--reset`) сбрасывает сетевые настройки без запуска службы. `--fix-ttl` применяет только настройку TTL.

## Логи и диагностика

Логи записываются в `Flowery\logs` внутри системной папки «Документы» (она может быть перенесена в OneDrive). Переменная `FLOWERY_HOME` меняет корень каталога логов на `%FLOWERY_HOME%\logs`; она не переносит конфигурацию и базу стратегий.

При сбое сохраните лог после воспроизведения проблемы и укажите профиль, способ подключения, сервис и примерное время сбоя. Особенно полезно различать загрузку сайта Discord, его изображений и голосового канала: они используют разные соединения.

Пункт `18` формирует диагностический отчёт с фильтрацией пользовательских путей и IP. В конфигурации выбран сервер-шлюз; прямые Telegram и Discord-транспорты также реализованы. Серверная часть находится в [relay](relay/README.md). Токены Telegram следует хранить в секретах сервера, а не в документации или распространяемой конфигурации.

## Разработка и проверки

```powershell
python tests/run.py
python tests/run.py --pattern test_batch_elevation.py
python -m compileall -q flowguard tests
```

`tests/run.py` создаёт временную копию исходников и тестовых ресурсов. Логи и оценки стратегий остаются внутри неё. Автономный прогон запрещает внешние сетевые обращения и завершается с ошибкой при их обнаружении, даже если код перехватил исключение. Проверки BAT выполняются в `cmd.exe` с подменой системных команд и точки входа приложения.

Отдельный запуск проверки TLS 1.3 с внешними серверами:

```powershell
python tests/run.py --integration
```

Этот результат зависит от доступности сети. Автономные тесты не доказывают работоспособность обхода у конкретного оператора.

## Структура исходников

- `flowguard/` — прокси, стратегии, DNS, управление Windows, консоль и трей.
- `Floweryguard/__init__.py` — совместимость со старым именем пакета.
- `tests/` — автономные проверки; `tests/integration/` — проверки внешней сети.
- `relay/` — Cloudflare Worker для приёма диагностических отчётов.
- `zapret_bin/` — внешние компоненты WinDivert/winws и шаблоны пакетов.
- `Flowery_Release/` — существующая локальная копия комплекта; часть регрессионных тестов сверяет её с основными файлами. Разработка ведётся в `flowguard/`.

Архивы и EXE в рабочей папке могут относиться к прежним сборкам. Для опубликованного комплекта сверяйте версию и SHA-256 с соответствующим выпуском в [Releases](https://github.com/KarlMerkel/Floweryguard/releases). Локальную сумму можно получить командой `Get-FileHash .\Flowery.exe -Algorithm SHA256`.
